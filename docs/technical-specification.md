# Техническое задание

## 1 Введение

System Monitor — учебный программный комплекс для наблюдения за ресурсами Mac и просмотра текущих показателей на Android. Рабочее место включает настольную программу с графическим интерфейсом, SQLite и локальный сервер HTTP. Мобильное приложение запускается в эмуляторе Android на том же Mac.

## 2 Основания для разработки

Основанием является индивидуальное задание на учебную практику «Разработка программного комплекса мониторинга и управления ресурсами компьютерной системы System Monitor» по специальности 09.02.07 «Информационные системы и программирование». Объём практики составляет 72 академических часа. Задание устанавливает требования к реализации, испытаниям, истории разработки и комплекту сдачи. Реквизиты утверждения задания указывает учебная организация.

## 3 Назначение разработки

Программа предназначена для получения и отображения живых показателей ЦП, ОЗУ и накопителей, просмотра истории, работы с файлами в выбранном каталоге и управления тестовыми дочерними процессами. Android-клиент показывает состояние Mac через HTTP и сообщает о потере соединения.

## 4 Требования к программе или программному изделию

### 4.1 Функциональные характеристики

| Код | Требование |
|---|---|
| MON | Получать реальные данные ЦП, физической памяти и смонтированных томов средствами macOS. Обновлять текущие показатели автоматически. |
| GUI | Показывать два графика с ограничением в 60 точек и анимированную полосу заполненности выбранного тома. Подписывать показатели и единицы измерения на русском языке. |
| FILE | Выбирать рабочий каталог, просматривать его дерево, создавать, копировать, перемещать, переименовывать и удалять объекты. Отображать свойства и менять признак «Только чтение». |
| PROC | Показывать PID, название и RSS. Запускать выбранный исполняемый файл и тестовый процесс. Завершать с подтверждением только дочерние процессы текущего экземпляра программы. |
| DATA | Автоматически создавать SQLite, записывать замеры, настройки и события. Показывать историю за период и журнал. Запрашивать подтверждение перед их раздельной очисткой. |
| API | Предоставлять GET /api/status и GET /api/health на локальном интерфейсе. Согласовывать текущий снимок и накопитель с настольным окном. |
| AND | Показывать имя компьютера, состояние связи, проценты ЦП, памяти и диска, дату и время получения. Предусмотреть ручное и автоматическое обновление, проверку связи и сохранение настроек. |

Состояние оборудования, результаты операций и доступность API отображаются в соответствующих вкладках. Интервалы обновления и записи на Mac задаются от 1 до 3 600 секунд, порт — от 1 024 до 65 535. Начальные интервалы составляют 2 и 10 секунд, порт — 8080. Android использует интервал от 1 до 3 600 секунд и проверяет номер порта от 1 до 65 535.

### 4.2 Надёжность и ограничение операций

Программа показывает «Недоступно» для отсутствующих показателей. Ошибки отдельных компонентов должны оставлять окно доступным. В Android при ошибке связи последние показания явно помечаются как устаревшие. Сбор показателей, обработка файловых операций и сетевые запросы выполняются в рабочих потоках.

Файловые операции разрешены внутри выбранного каталога. Опасные операции требуют подтверждения. Конфликт имён сохраняет существующий объект. Ссылки проверяются при выполнении файловых операций. API обслуживает операции просмотра состояния. Настройки и журнал сохраняются между запусками.

### 4.3 Условия эксплуатации и состав технических средств

Настольная часть предназначена для Mac с macOS 13 или новее. Для выполнения используется Python 3.12. На испытательном стенде использован Mac Apple M2 с 8 ГиБ ОЗУ. Для проверки Android на этом Mac требуется Android Studio, SDK и один эмулятор. Клиент устанавливается на Android 13 или новее. Настройку выполняет оператор с правами на выбранный каталог.

### 4.4 Информационная и программная совместимость

Настольная программа использует PySide6, psutil, Flask и встроенный модуль sqlite3. Клиент написан на Kotlin, использует Android SDK и HttpURLConnection. По HTTP передаётся JSON в UTF-8. Время в сетевом ответе передаётся в ISO 8601 UTC. В SQLite время хранится в миллисекундах Unix. Суммарные объёмы указываются в байтах, использование ресурсов — в процентах.

### 4.5 Комплект поставки и хранение

Комплект содержит исходный код, схему SQLite, тесты, инструкцию сборки, установочный APK Android и программную документацию. Исходники хранятся в системе контроля версий. Архивирование данных пользователя выполняется средствами операционной системы с закрытым приложением. Специальные требования к маркировке и упаковке учебного комплекта отсутствуют.

### 4.6 Специальные требования

Интерфейсы Mac и Android ведут диалог с оператором на русском языке. Файловые проверки выполняются в отдельной учебной папке. Сетевые проверки проводят на локальном стенде.

## 5 Требования к программной документации

Представить техническое задание, описание программы, программу и методику испытаний и руководство оператора отдельными PDF. Дополнительно представить архитектурную схему, схему SQLite, не менее пяти алгоритмов, протокол испытаний, описание отладки, результаты рефакторинга и оптимизации, инструкцию сборки и отчёт по практике.

## 6 Технико-экономические показатели

Комплекс выполняется в пределах 72 академических часов. Хранилище SQLite и локальный API развёртываются на учебном Mac. Для работы не требуется выделенный сервер или платная подписка. Для оценки эффективности следует выполнить сравнимые замеры файловой операции до и после оптимизации. Коммерческие показатели и стоимость внедрения в рамках практики не рассчитываются.

## 8 Порядок контроля и приёмки

Контроль выполняют по программе и методике испытаний. Проверяют все группы требований раздела 4, не менее двадцати функциональных сценариев, не менее восьми автотестов и повторный прогон после изменений. На защите демонстрируют реальные замеры, файловую операцию, запуск и завершение тестового процесса, записи SQLite, успешное подключение Android и обработку разрыва связи. Решение о приёмке принимает преподаватель.
