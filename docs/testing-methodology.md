# Программа и методика испытаний

## 1 Объект испытаний

System Monitor включает настольное приложение macOS, SQLite, локальный HTTP API и приложение Android в виде APK. На испытания представляется сборка из проверяемой версии исходного кода с инструкцией по запуску.

## 2 Цель испытаний

Подтвердить, что комплекс получает реальные показатели, корректно выполняет штатные операции и обрабатывает ошибки. Проверить согласованность окна и API, устойчивость сохранённых данных и отображение состояния связи на Android. Повторить проверки после исправлений, рефакторинга и оптимизации.

## 3 Требования к программе

Проверяются группы требований MON, GUI, FILE, PROC, DATA, API и AND технического задания. Проценты должны находиться в диапазоне 0–100. Операции с файлами выполняются в тестовой рабочей папке. Управление процессами ограничивается запущенными через System Monitor дочерними процессами. SQLite создаётся автоматически. API отдаёт данные текущего снимка. Android различает свежие и устаревшие сведения.

## 4 Требования к программной документации

На испытания представляют техническое задание, описание программы, настоящую методику, руководство оператора и README. Результаты отмечают отдельно в протоколе с фактическим результатом, статусом, сведениями о дефектах и данными повторного прогона.

## 5 Средства и порядок испытаний

Стенд включает Mac, Python 3.12, PySide6, SQLite, Android Studio, SDK, Gradle Wrapper и эмулятор Pixel. Используются unittest, JUnit, Android Lint, Qt Test и ADB. Для проверки API используются HTTP-запросы к локальному интерфейсу. Для файлов и базы подготавливаются отдельные временные каталоги. Контрольные данные для фильтра и имитация недоступности оборудования используются в обозначенных сценариях.

1. Собрать APK и установить его в запущенный эмулятор. Создать временную рабочую папку и отдельную тестовую SQLite.
2. Запустить настольную часть и проверить аппаратные данные, графики, файловые операции и процессы.
3. Проверить запись истории, фильтр, настройки и журнал. Выполнить запросы к серверу с Mac.
4. Открыть Android и проверить получение данных, ручное и автоматическое обновление, неверные настройки и потерю связи.
5. Запустить автотесты Python и Kotlin. После исправлений повторить сценарии и зафиксировать результаты отдельно.

```text
.venv/bin/python -m unittest discover -s tests -v
./gradlew testDebugUnitTest lintDebug
```

Команда Python выполняется из корня проекта, Gradle — из каталога mobile.

## 6 Методы испытаний

Штатные операции проверяют по наблюдаемому результату и состоянию ресурсов. Для отрицательных сценариев используют недоступные источники, ошибочные пути и адреса, конфликт имён и занятый порт. При перезапуске проверяют сохранение данных. Согласованность интерфейса и API подтверждают сравнением значений и отметки времени одного снимка. Производительность оценивают медианой сопоставимых измерений до и после изменений.

Сценарий получает Passed, если выполнены все ожидаемые условия. Несоответствие отмечают как Failed и регистрируют дефект. Blocked означает, что проверку нельзя выполнить из-за известной причины. Not Run означает, что проверку ещё не запускали. К приёмке допускается реализация, которая проходит обязательные функциональные сценарии и автотесты.

### А.1 Оборудование

| Сценарий | Действия и входные данные | Ожидаемый результат |
|---|---|---|
| HW-01 Системные показатели | Запустить мониторинг и дождаться первого замера Mac. | ЦП, ОЗУ и накопители прочитаны из macOS. Проценты находятся в диапазоне 0-100. |
| HW-02 Недоступность показателей | Подменить чтение ОЗУ и дисков исключением OSError. Снять новый замер. | Недоступные поля пусты. Получение сведений о ЦП продолжается. |

| Сценарий | Действия и входные данные | Ожидаемый результат |
|---|---|---|
| FILE-01 Создание и переименование | Выбрать временную папку. Создать две папки и файл «замер.txt», заполнить его и переименовать. | Все объекты видны. Новое имя принято, содержимое сохранено. |
| FILE-02 Копирование и перемещение | Скопировать «записка.txt» в «Документы», переместить оригинал в «Архив». Открыть «Документы». | Обе копии содержат одинаковый текст. Исходный путь освобождён после перемещения. |
| FILE-03 Свойства и атрибут | Выделить файл, проверить расширение и путь, включить «Только чтение». | Показаны свойства выбранного файла. Атрибут изменён. |
| FILE-04 Удаление с подтверждением | Нажать «Удалить». Сначала отменить, затем подтвердить. Вернуться в корневую папку. | При отмене файл остаётся. После подтверждения удалён, навигация работает. |
| FILE-05 Конфликт и границы | Создать одноимённый файл. Запросить копирование наружу и во вложенную ссылку наружу. | Операции отклонены. Существующие файлы остаются без изменений. |
