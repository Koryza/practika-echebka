# Отладка System Monitor

## Задержка запуска HTTP API

При первом запуске тест HTTP API не дошёл до проверки запроса. Отдельный запуск с `faulthandler.dump_traceback_later(4)` показал, что через четыре секунды Python всё ещё выполнял обратный поиск имени для локального адреса. Стек вызовов прошёл через `wsgiref.simple_server`, затем через `http.server` к `socket.getfqdn`.

Сервер теперь привязывает TCP-сокет к `127.0.0.1` и передаёт этот адрес в WSGI как имя сервера. Для привязки используется числовой адрес. Поиск имени убран из этого пути.

При повторной проверке сервер запустился, ответил на запрос состояния и сохранил прежний порт при конфликте. Автотест подменяет `socket.getfqdn` функцией, которая сообщает об ошибке при вызове, и проверяет запуск сервера и ответ на реальный HTTP-запрос.

## Возврат с экрана настроек Android

Первая сборка Android установилась и получила показатели Mac. Команда `lintDebug` обнаружила ошибку `GestureBackNavigation`. В активности оставался обработчик `onBackPressed`, который на Android 16 и новее не вызывается для жеста «Назад».

Экран настроек регистрирует системный `OnBackInvokedCallback` при открытии и снимает регистрацию при возврате к мониторингу. Минимальная версия приложения — Android 13, где доступен этот интерфейс. После исправления сборка и `lintDebug` завершились успешно.

## Проверка адреса Android

Сценарий AND-04 выявил, что поле адреса принимало `bad/path` и запускало сетевую проверку. Модульный тест с тем же входом подтвердил дефект.

Причину проверили на коротком воспроизведении вызова `URI` в отладчике `jdb`. Точка останова и команды `where`, `locals` и `next` показали, как библиотека разделила строку на узел `bad` и путь `/path`. В исходной проверке учитывался узел, а остальные части адреса могли остаться незамеченными.

Проверка теперь отклоняет адреса с путём, параметрами запроса или фрагментом. Три модульных теста на Kotlin проверяют допустимые адреса, запрещённые части адреса, диапазоны портов и интервалов.
